# 대사 텍스트 엔진 조사 (2026-10-05)

대상: `Gambler Densetsu Tetsuya - Yomigaeru Densetsu (Japan).gba` (헤더 TETSUYA / ATYJ / E7, 8 MiB,
SHA-256 `65e8eb749a88c18c02ea8bf783b62f0cd7a39f0e38f550e7be124172016c08bd`).
근거는 모두 정적 디스어셈블(capstone, Thumb)과 ROM 데이터 교차 검증이며, 실행 관측은 `work/emucap/`에 둔다.

## 1. 관찰과 결론

- 평문 Shift-JIS는 약 4 KB뿐이며 본편 대사가 아니다(그래픽 데이터의 우연한 일치 포함). BIOS LZ77 헤더 블록 5개에도 텍스트 없음.
- 본편 대사는 **자체 2바이트 글리프 코드 + 1바이트 제어코드** 스트림이다. 해석기는 `0x080325e0` 함수(Thumb)이며
  상태 구조체(`0x03001430`) 필드 `+0x25`=bank, `+0x26`=sub, `+6`=message index(u16), `+8`=byte cursor, `+9`=column.
- 메시지 주소 = `[[[0x082188ec + bank*4] + sub*4] + msg*4]` (모두 ROM 절대주소, LE u32). bank 11개(0..10)를 확인했고
  12번째 항목은 테이블 자신을 가리키는 더미다. sub 테이블은 많은 bank에서 공유 포인터(`0x08200b44` 빈 테이블 등)를 포함한다.
- 바이트 디스패치: `0x10..0xFF`는 점프 테이블 `0x080326d8`(240항목), `0x00..0x0F`는 문자 핸들러로 직행.
  점프 테이블의 기본 항목도 문자 핸들러(`0x08032ef8`)이므로 **첫 바이트가 제어코드가 아니면 2바이트 글리프 코드(상위, 하위 순)**다.

두 번째 바이트를 추가로 읽는다.

### 문자 그리기 (`0x08032f28`)

- 인수: hi, lo, column. 글리프 포인터 = `[[0x0821b1b8 + hi*4] + lo*4]` → 256바이트 글리프.
- 글리프 = 16×16, 8bpp, 8×8 타일 4개(좌상·우상·좌하·우하) 순. 픽셀 값 0=투명, 1·2=색(팔레트 인덱스).
- `0x0803302c`가 글리프를 줄 버퍼(`0x03002740`)에 **0이 아닌 픽셀만 덮어쓰기**로 합성하며, 짝수 열은 타일 경계에, 홀수 열은
  4px 오프셋에 놓는다. 즉 **표시 피치는 12px**, 한 줄 18칸(216px), 창은 2줄. DMA로 `0x0600a340`(1행)과 `0x0600b0c0`(2행)에 전송.
- 글리프 포인터 테이블은 bank 0..3(`0x0821a2a0`, `+0x400`씩)만 유효하며 966개 코드(`0x000..0x3c5`)가 `0x44eafc..0x48b6fc`를
  가리킨다. hi 바이트 4 이상은 테이블 범위를 벗어나므로 확장하려면 bank 테이블 자체를 옮겨야 한다(참조 리터럴 2곳:
  `0x08032fa8`, `0x08033020`).

### 글리프 신원

`config/glyph_transcription.txt`는 렌더링한 아틀라스를 사람이 전사한 결과이고, `tools/build_glyph_table.py`가 ROM 포인터와
대조해 `config/glyph_table.json`을 만든다. 글리프는 스크립트 등장 순서대로 배치돼 있다(히라가나, 가타카나, 그다음 한자).
중복 자형 9쌍(着·速·両·浪·業·壁·貧·者·腰)은 그대로 유지한다. 복호 결과가 자연스러운 일본어로 읽힘을 bank 0·3·8 샘플로 확인했다.

## 2. 모집단과 분량

`tools/extract_script.py` 결과(`assets/translation/index.json`): 고유 메시지 **2,564개**, 글리프 코드 **40,811자**(정확값, 대사 엔진 기준).
메시지 사이 199개의 틈은 참조되지 않는 바이트(미참조 메시지 또는 데이터)이며 보호 영역으로 둔다.
`{?0c03}` 같은 미매핑 코드 9건은 원본 자체의 상위 바이트 0x0c 등 범위 밖 값으로, 원본에서도 쓰레기 글리프를 그린다.

대사 엔진 밖의 텍스트(타이틀 로고, 메뉴, 마작 UI)는 그래픽 가능성이 높고 별도 조사 대상이다. → `docs/status.md`.

## 3. 기각한 해석

- 16-bit LE 코드 스트림: 메시지 시작 주소가 홀수이고 핸들러가 `ldrb` 두 번으로 읽는다.
- 0xFF만 종료: 0xFD도 종료(자동 진행)이며 `0xFE 0xFD`로 끝나는 메시지 66건이 경계 불일치를 일으켰다가 해소됐다.
- 0x3bc27c의 `82 e1` 반복(SJIS 'ゃ'처럼 보임)은 텍스트가 아니라 그래픽/패딩이다.
